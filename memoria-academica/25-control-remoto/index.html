25. Ampliación: control de varios ordenadores (ARVI Remote)

5 min de lectura

#25.1 Justificación

El alumno trabaja con dos equipos: ARVI-SERVER (el portátil i9-12900HK donde corren ARVI, n8n, VoiceStudio y Home Assistant) y un PC de edición con RTX 3050 Ti. Lo útil es poder decir «¿cómo va el render en el PC de edición?» o «abre DaVinci en el sobremesa» sin levantarse.

El requisito de seguridad manda sobre todo lo demás:

  • nada expuesto a Internet: ni puertos públicos ni Tailscale Funnel;
  • ningún acceso oculto ni persistencia sin conocimiento del usuario: el agente es visible, identificable y desinstalable;
  • ninguna shell remota libre controlada por el modelo.

#25.2 Comparativa de enfoques

Enfoque Ventajas Inconvenientes Decisión
Control local (ToolRegistry en ARVI-SERVER) Ya existía (capítulo 13) Solo actúa sobre el propio servidor Se mantiene para ARVI-SERVER
API REST en cada PC (el servidor llama al PC) Simple Hay que abrir un puerto en cada PC; el PC debe ser alcanzable Descartado
Escritorio remoto, SSH o WinRM Potentes Dan una shell completa; contradicen el requisito Descartado
Agente que se conecta hacia fuera (WebSocket saliente por la tailnet) No abre puertos en el PC; funciona tras NAT; capacidades cerradas Hay que instalar un programa pequeño en cada PC Elegido

#25.3 Arquitectura

Componente Archivo Función
Registro backend/arvi/remote/core.py (DeviceRegistry) SQLite data/equipos.db. El token se muestra una vez; se guarda solo su hash SHA-256 y se verifica con hmac.compare_digest
Política DevicePolicy + config/equipos.yaml Nivel por capacidad y por equipo; solo puede endurecer niveles, nunca rebajarlos
Concentrador AgentHub Sesiones, latido (20 s; desconectado tras 60 s), llamadas con tiempo máximo, cancelación, revocación e historial
Herramientas backend/arvi/tools/device_tools.py equipos_lista (0), equipos_estado (0), equipos_accion (nivel de la capacidad), equipos_coordinar (el mayor de sus pasos)
Agente agent/arvi_agent.py Programa independiente para el otro PC; token cifrado con DPAPI
Instalación agent/instalar.ps1, agent/desinstalar.ps1 Instala en %LOCALAPPDATA%\ARVI-Agent con un acceso directo visible en el menú Inicio; el arranque automático es opcional (-AutoInicio)
API GET/POST /api/equipos, DELETE /api/equipos/{id}, POST /api/equipos/{id}/tareas, WS /ws/agent Panel «Ordenadores»

#Protocolo

  1. El agente abre wss://servidor.<tailnet>.ts.net/ws/agent y envía hola con su id, su token, la versión, datos básicos del equipo y su catálogo (apps, carpetas y tareas que permite). El catálogo no incluye rutas ni órdenes, solo identificadores.
  2. Si el token es incorrecto, el servidor cierra con el código 4401. Si el equipo está revocado, con el 4403, y el agente se detiene con código de salida 2, sin reintentar.
  3. El servidor responde bienvenido. Cada 20 s llega un latido con CPU y RAM.
  4. Cada acción viaja como tarea {id, capacidad, argumentos} y vuelve como resultado o progreso. Si se agota el tiempo, el servidor envía cancelar.
  5. Si el mismo equipo se conecta dos veces, la sesión nueva sustituye a la antigua (código 4409).

#25.4 Capacidades y doble lista blanca

Una acción solo se ejecuta si la permiten las dos partes: el servidor (config/equipos.yaml) y el propio PC (agente.yaml, que el usuario edita en ese equipo).

Capacidad Nivel Qué hace Límite en el agente
sistema 0 CPU, RAM, discos, tiempo encendido —
procesos 0 Procesos que más memoria usan Sin líneas de órdenes
listar_archivos 0 Contenido de una carpeta Solo carpetas de agente.yaml
leer_archivo 0 (2 en PC-SECUNDARIO) Texto de un archivo Tamaño máximo, sin salir de la carpeta
abrir_app 1 Abre una app Solo apps de agente.yaml
escribir_archivo 2 Crea, sobrescribe (con copia .arvi-bak) o añade Solo carpetas con escritura: true
tarea 3 Ejecuta una tarea preconfigurada argv fijo, sin shell, con tiempo máximo
cancelar 1 Cancela una tarea en curso —

No hay ninguna capacidad de terminal. Una prueba comprueba que shell ni siquiera es un valor válido del esquema de la herramienta.

#25.5 Coordinación entre equipos

equipos_coordinar ejecuta un plan de varios pasos en paralelo por equipo. Cada paso devuelve uno de estos estados: completado, fallido, pendiente (equipo desconectado), bloqueado, denegado o aclaracion (nombre ambiguo). El resultado se envía al workflow de n8n «ARVI · Coordinación de equipos», nuevo y separado de los del usuario. El workflow devuelve un informe con el estado global, el recuento y un resumen por paso.

Si el usuario dice «el ordenador» y no queda claro cuál, ARVI pregunta. Por ejemplo: «¿Te refieres a ARVI-SERVER o a otro ordenador registrado?».

#25.6 Pruebas

Las pruebas REAL se ejecutan con el agente real lanzado como proceso aparte en ARVI-SERVER. El agente se conecta por la tailnet (wss://servidor.TU-TAILNET.ts.net), igual que lo hará el segundo PC (scripts/e2e/equipos.py, evidencia docs/pruebas/evidencias/equipos-2026-11-12.json).

ID Prueba Resultado
R1 Registro con token mostrado una vez OK — solo se guarda el hash
R2 Conexión saliente por Tailscale y token DPAPI OK — conectado en 0,51 s
R3 Estado (CPU, RAM, discos) OK — 503 ms
R4 Procesos OK — sin líneas de órdenes
R5 Abrir app de la lista blanca OK — Bloc de notas, 1 proceso nuevo
R6 App no permitida y capacidad inexistente OK — cmd rechazada por el agente; shell bloqueada por el servidor
R7 Crear archivo OK — queda pendiente de confirmación y solo se escribe tras aprobarla
R8 Ruta fuera de la carpeta OK — PermissionError
R9 Tarea preconfigurada y cancelación OK — salida correcta; cancelada a los 271 ms
R10 Revocación OK — el agente sale con código 2 y no puede volver a entrar
R11 Equipo no indicado OK — ARVI pregunta cuál
R12 Coordinación con informe en n8n OK — n8n registra «ARVI-SERVER-PRUEBA → sistema: completado | PC-SECUNDARIO → sistema: pendiente»

Además hay 16 pruebas MOCK (tests/unit/test_remote.py), con un agente simulado en memoria y las capacidades reales del agente sobre carpetas temporales. Registro: P-047 y P-048.

PENDIENTE Pruebas con el segundo PC físico: instalar el agente en el PC de edición y repetir R2–R10 desde allí. Requiere que el alumno ejecute el instalador en ese equipo (no se pueden dar por superadas desde ARVI-SERVER).

#25.7 Instalación en el PC de edición

  1. Instalar Tailscale en el PC de edición con la misma cuenta, y Python 3.10 o superior.
  2. Copiar la carpeta agent/ al PC.
  3. Ejecutar powershell -ExecutionPolicy Bypass -File instalar.ps1 -Id <id del equipo> y pegar el token que se mostró al registrarlo. El token se guarda cifrado con DPAPI y nunca en texto plano.
  4. Editar agente.yaml para decidir qué apps, carpetas y tareas se permiten. Por ejemplo: abrir DaVinci Resolve, leer la carpeta de renders de E:, o ninguna carpeta de D:.
  5. Para quitarlo: desinstalar.ps1. Para revocarlo desde ARVI: botón «Revocar acceso».

#25.8 Limitaciones

  • El agente solo funciona mientras su ventana está abierta, salvo que se elija -AutoInicio.
  • Las tareas son preconfiguradas; ARVI no puede inventar órdenes nuevas. Es una limitación deliberada.
  • No hay transferencia de archivos grandes entre equipos.
