6. Planificación del proyecto

2 min de lectura

#6.1 Metodología

Se sigue un desarrollo incremental e iterativo por fases. Cada fase entrega un incremento funcional que se prueba y se documenta antes de pasar a la siguiente. La regla de cierre es estricta: una fase no se considera terminada sin pruebas ejecutadas y documentación actualizada.

El desarrollo se apoya en un asistente de programación con IA (ver el anexo de uso de IA), bajo la dirección del alumno, que define los requisitos, autoriza cada acción sobre el sistema y revisa los resultados.

#6.2 Fases

Fase Contenido Estado
0 Preparación: análisis del entorno, herramientas, estructura, documentación Completada (2026-11-12)
1 Núcleo: FastAPI, OpenAI, chat, historial, streaming Completada (P-007, P-039)
2 Memoria: bóveda Obsidian, indexación, recuperación Completada (P-005 a P-008)
3 Voz: VoiceStudio, STT/TTS, interrupciones Completada (P-012 a P-016; voz definitiva en P-044)
4 Interfaz: React, esfera Completada (P-019, P-040)
4b Escritorio: Tauri 2 Completada (P-034, P-035)
5 Herramientas y seguridad: permisos, auditoría, OWASP Completada (P-009 a P-011, P-027)
6 Automatizaciones: n8n Completada (P-024 a P-026)
7 Servicios externos: Google, GitHub Parcial: GitHub REAL; Google pendiente de la credencial del alumno
8 Acceso móvil: PWA, Tailscale Parcial: PWA completa; falta que el alumno active tailscale serve
9 Consolidación: accesibilidad, latencia, auditoría de dependencias, instalación limpia, sustitución del TTS obsoleto Completada (P-039 a P-044)
10 Entrega académica: conclusiones, mejoras, anexos, Word y web Completada; faltan los datos de portada y las horas, que aporta el alumno

#6.3 Cronograma y registro de horas

Las fechas y las horas se toman exclusivamente del diario de desarrollo. No se estiman horas que no se hayan registrado.

Sesión Fecha Fases trabajadas Horas registradas
1 2026-11-12 0 a 10 (sesión continua, con varias reanudaciones; ver el diario) [PENDIENTE: el alumno debe anotar la duración real]

El diario registra el orden real del trabajo en esa sesión: núcleo, prueba real con OpenAI, voz, interfaz, n8n, seguridad OWASP, PWA, Tauri, GitHub, consolidación y entrega. Las horas no se reconstruyen a posteriori.

#6.5 Riesgos

Riesgo Probabilidad Impacto Mitigación
Latencia alta de la voz local sin GPU Alta Media Se materializó con la voz clonada (INC-020): síntesis frase a frase, 4 pasos, el texto llega antes
Retirada de modelos de OpenAI Alta Media Se materializó con el TTS (retirado el 2027-01-06): sustituido por la Realtime API (P-043)
Servicio crítico del alumno en el mismo equipo Media Alta Vigilancia del túnel; descargas avisadas; procesos pesados con prioridad baja (INC-011, INC-019)
Coste de la API de OpenAI Media Media Registro de tokens por petición; modelo eficiente por defecto
Prompt injection a través de datos Media Alta Permisos en backend; datos marcados como no instrucciones
Exposición de n8n a Internet (túnel existente) Media Alta ARVI usa solo loopback; recomendación documentada
Cambios en APIs externas Media Media Adaptadores aislados tras interfaces
