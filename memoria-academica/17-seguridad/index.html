17. Seguridad y privacidad

4 min de lectura

#17.1 Modelo de amenazas (resumen)

Referencias: OWASP Top 10 (2021), OWASP Top 10 para aplicaciones con LLM y OWASP API Security Top 10. La columna «Prueba» remite a tests/security/test_owasp.py (P-027) o a otras baterías.

#17.2 Defensa en profundidad frente a la inyección de instrucciones

Ninguna técnica garantiza que un modelo de lenguaje ignore órdenes escondidas en los datos. ARVI combina tres capas:

  1. Marcado de datos. Todo contenido externo llega al modelo dentro de una etiqueta que las reglas de config/personality.yaml declaran como datos. wrap_untrusted() neutraliza dentro del contenido cualquier apertura o cierre de esa etiqueta (también con mayúsculas o espacios) y escapa los atributos.
  2. Herramientas cerradas. El modelo no puede pedir nada que no esté en el catálogo, y los argumentos se validan con esquemas cerrados.
  3. Permisos en el backend. Las acciones sensibles necesitan la aprobación del usuario. La prueba test_even_if_model_obeys_injection_sensitive_action_needs_approval simula el peor caso: el modelo obedece la orden inyectada y pide borrar una nota. La nota queda intacta hasta que el usuario lo aprueba.

#17.3 Hallazgos sobre la infraestructura existente

Ver el capítulo 12: túnel público de Cloudflare hacia n8n y puerto 5678 en 0.0.0.0. Se han comunicado al usuario sin modificar nada. Los webhooks de ARVI exigen token, así que no se pueden lanzar desde el túnel sin conocerlo (comprobado en P-025: token incorrecto → 403).

#17.4 Protección de datos (RGPD)

ARVI trata datos personales de un único usuario, que es a la vez el responsable del tratamiento. Se aplican los principios de minimización (no se guardan conversaciones completas en la bóveda), limitación de la finalidad, derecho de supresión (borrado de conversaciones y recuerdos desde la API) e integridad y confidencialidad. Los datos enviados a OpenAI se limitan al contexto de cada petición, con store=False. No hay todavía una política de retención configurable: el historial se borra a mano desde la API (capítulo 22).

#17.5 Cadena de suministro (OWASP A06)

El 2026-11-12 se auditaron todas las dependencias (P-041):

Herramienta Alcance Resultado
pip-audit 69 paquetes Python (exportados de uv.lock) 0 vulnerabilidades
npm audit 187 paquetes del frontend 0 vulnerabilidades
cargo audit 458 crates de Tauri 0 vulnerabilidades; 5 avisos en dependencias solo de Linux (GTK, D-Bus), que no se compilan en Windows

Las tres auditorías se ejecutan además en la integración continua (.github/workflows/ci.yml), así que una vulnerabilidad nueva publicada en una dependencia hará fallar la CI. Las versiones están fijadas con archivos de bloqueo (uv.lock, package-lock.json, Cargo.lock), y la instalación limpia los respeta (uv sync --frozen, npm ci; P-042).
