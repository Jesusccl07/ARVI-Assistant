11. Memoria persistente con Obsidian

3 min de lectura

#11.1 Principio de diseño

La memoria duradera de ARVI son archivos Markdown en una bóveda de Obsidian. El usuario puede leerlos, corregirlos o borrarlos con Obsidian, y ARVI detecta esos cambios. El índice de búsqueda de SQLite es secundario y se puede reconstruir.

La bóveda (Documents\ARVI-Memory) está fuera del repositorio Git, y el backend se niega a arrancar si ARVI_VAULT_PATH apunta dentro del repositorio (prueba test_vault_inside_repo_is_refused).

#11.2 Estructura de la bóveda

Carpeta Categoría Uso
00-Inbox inbox Recuerdos sin clasificar
01-Perfil perfil Datos estables del usuario
02-Preferencias preferencias Gustos y configuraciones
03-Proyectos proyectos Objetivos, tareas y decisiones de proyectos
04-Personas personas Contactos relevantes
05-Conocimiento conocimiento Información de referencia
06-Decisiones decisiones Decisiones tomadas
07-Resúmenes resumenes Resúmenes episódicos
08-Automatizaciones automatizaciones Notas generadas por n8n
09-Sistema sistema Notas internas de ARVI
99-Archivo archivo Recuerdos archivados (borrado lógico)

#11.3 Operaciones

Operación Implementación
Crear Escritura atómica (archivo temporal + os.replace) para no dejar notas a medias
Detectar duplicados Mismo título y categoría → se actualiza la nota existente en vez de duplicarla
Actualizar Reescribe la nota; si cambia el título, renombra el archivo y elimina el anterior
Eliminar Por defecto archiva (mueve a 99-Archivo); el borrado físico es explícito
Buscar FTS5 con remove_diacritics (insensible a acentos), palabras vacías filtradas y prefijos
Reindexar Incremental: compara mtime y SHA-256 de cada archivo con el índice
Obsoletos stale(días) lista los recuerdos activos que no se han actualizado en ese plazo
Backup ZIP de la bóveda; la restauración protege frente a zip slip

#11.4 Protección de datos sensibles

secrets_filter.find_sensitive() bloquea, en el backend, la escritura de claves de OpenAI, tokens de GitHub, claves de Google, claves privadas, JWT, contraseñas, IBAN y números de tarjeta (estos últimos validados con el algoritmo de Luhn para reducir falsos positivos):

("contraseña", re.compile(
    r"(?i)\b(contrase[ñn]a|password|passwd|pwd|clave|pin)\b\s*(es|:|=)\s*\S+")),

Es una defensa heurística: reduce el riesgo, pero no detecta todos los casos posibles.

#11.5 Recuperación contextual y procedencia

En cada turno el agente busca recuerdos relacionados con el mensaje del usuario y los incluye en las instrucciones del modelo así:

<recuerdo id="24aa4aa3f9" nota="03-Proyectos/proyecto-final--24aa4aa3f9.md" actualizado="...">
Mi proyecto final de Grado Superior se llama ARVI.
</recuerdo>

La respuesta incluye la lista memories con el título y la ruta de cada nota usada, de modo que la interfaz puede mostrar el origen. Esto equivale a una técnica RAG (Retrieval-Augmented Generation) léxica.

#11.6 Política de escritura

ARVI_MEMORY_WRITE_POLICY=auto permite que ARVI guarde recuerdos de nivel 1 directamente; confirm exige la aprobación del usuario para cada recuerdo nuevo. ARVI no guarda las conversaciones completas en la bóveda: solo lo que el modelo decide recordar mediante la herramienta memory_remember.

#11.7 Pruebas

17 pruebas automatizadas (ver capítulo 18) y una prueba real (P-005, P-006): la nota 03-Proyectos/proyecto-final--24aa4aa3f9.md se creó en la bóveda real mediante la API y se recuperó después de reiniciar el servidor.
