9.1 Interfaz LLMProvider

El agente se comunica con el modelo a través de una interfaz neutra (providers/llm/base.py):

class LLMProvider(Protocol):
    name: str
    model: str

    async def complete(self, *, instructions: str, items: list[ChatItem],
                       tools: list[ToolSpec],
                       on_text_delta: TextDeltaCallback | None = None) -> LLMResponse: ...

ChatItem representa mensajes, llamadas a herramientas y resultados en un formato propio de ARVI. Cada proveedor lo traduce al formato de su API. Sustituir el modelo o el proveedor solo exige una nueva clase que implemente complete.

9.2 Responses API

OpenAIProvider usa la Responses API oficial con el SDK openai 3.49.0. La firma de responses.create y los tipos de eventos se comprobaron en el paquete instalado antes de programar, para no basarse en supuestos:

  • Eventos usados: response.output_text.delta (fragmentos de texto) y response.completed (respuesta final con usage).
  • Llamadas a herramientas: elementos function_call con call_id, name y arguments; los resultados se devuelven como function_call_output.
  • store=False: OpenAI no conserva la conversación en su plataforma. ARVI envía en cada petición el contexto necesario. Se prioriza la privacidad sobre la comodidad de encadenar respuestas en el servidor (previous_response_id).

9.3 Elección del modelo

Según la página oficial de precios y modelos (consultada el 2026-11-12):

Modelo Entrada / salida ($ por millón de tokens) Observaciones
gpt-6-luna 0,10 / 0,50 "Nuestro modelo más eficiente para tareas acotadas y de alto volumen"; function calling, streaming y Responses API
gpt-5-nano 0,05 / 0,40 Más barato, pero obsoleto según OpenAI
gpt-6.1-terra 1,00 / 5,00 Elección inicial; 10 veces más caro que gpt-6-luna

Decisión (2026-11-12, a petición del alumno): durante el desarrollo se usa gpt-6-luna, el modelo vigente más barato compatible con herramientas. Se descarta gpt-5-nano por estar obsoleto. Si la calidad no basta, se sube de modelo cambiando ARVI_LLM_MODEL, sin tocar el código.

9.4 Gestión de errores

Los errores del SDK se traducen a mensajes en español sin datos sensibles:

Excepción del SDK Mensaje al usuario
AuthenticationError La clave de OpenAI no es válida o ha sido revocada
RateLimitError Límite de uso o de crédito alcanzado
NotFoundError El modelo no está disponible para esta cuenta
APIConnectionError / APITimeoutError No se puede conectar con OpenAI

Si falta la clave, el servidor arranca igualmente y /api/health lo indica (llm.ready: false), lo que se comprobó en la prueba P-003.

9.5 Métricas

Cada llamada registra en llm_usage el modelo, los tokens de entrada y salida y la latencia. Nunca se guardan claves ni el contenido de la petición. /api/usage ofrece el acumulado, que alimentará el cálculo de costes del capítulo 20.
