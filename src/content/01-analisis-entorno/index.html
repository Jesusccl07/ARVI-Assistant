Hallazgos de seguridad (n8n)

  1. WEBHOOK_URL apunta a un túnel rápido de Cloudflare (*.trycloudflare.com). Mientras el túnel esté activo, el panel de n8n y sus webhooks son accesibles desde Internet. Esto contradice el requisito "no exponer servicios administrativos directamente a Internet". Recomendación: no usar el túnel para ARVI; acceder a n8n solo por 127.0.0.1 desde el backend. ARVI no depende de ese túnel. No se ha modificado nada; la decisión es del usuario.
  2. Puerto 5678 publicado en 0.0.0.0. Cualquier equipo de la red local puede alcanzar n8n. Recomendación: publicarlo como 127.0.0.1:5678:5678 en el docker-compose.yml existente (requiere recrear el contenedor → solo con autorización explícita).

7. VoiceStudio

  • Repositorio verificado: https://github.com/debpalash/VoiceStudio — estudio de voz local (TTS, clonación y diseño de voces, transcripción con Whisper). Licencia de la aplicación: AGPL-3.0.
  • Soporta CPU, CUDA, Metal y Vulkan (GGUF). En este PC: CPU / Vulkan.
  • API local en 127.0.0.1:3900, sin autenticación en loopback por defecto; OMNIVOICE_API_KEY activa autenticación Bearer para clientes remotos.
  • Transcripción compatible con OpenAI: POST /v1/audio/transcriptions y streaming por WebSocket en /v1/audio/transcriptions/stream.
  • Síntesis: herramienta MCP generate_speech en /mcp/ (la ruta REST se confirmará contra el openapi.json del servidor instalado; no se presupone).
  • Instalación: script oficial install.ps1 revisado línea a línea antes de ejecutarlo (descarga el instalador de la release de GitHub y verifica SHA-256).
  • Licencias de modelos: ver docs/voz/licencias-modelos.md.

8. Decisión de plataforma

Arquitectura híbrida nativa en Windows:

  • Backend Python (FastAPI) ejecutado directamente en Windows (acceso al escritorio, apps y archivos locales, imprescindible para el agente local; dentro de Docker no podría abrir aplicaciones).
  • n8n en Docker (ya existente, reutilizado).
  • VoiceStudio nativo (aplicación Electron con backend local).
  • Frontend React/Vite servido por el backend como PWA; aplicación de escritorio con Tauri 2.

Se descarta ejecutar el backend en WSL o Docker porque el control del PC (abrir VS Code, ventanas, procesos) exige ejecución nativa en Windows.
