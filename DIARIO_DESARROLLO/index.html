    Diario de desarrollo de ARVI¶

    Registro cronológico de cada sesión de trabajo. Cada entrada recoge solo actividades realmente realizadas y verificables. Las incidencias técnicas se detallan en pruebas/incidencias.md y las pruebas en pruebas/registro-pruebas.md.

    Convención: el desarrollo se realiza con asistencia de IA (Claude Code, modelo Claude Opus 5.5), bajo dirección y supervisión del alumno. Ver memoria-academica/anexo-uso-ia.md.

    Sesión 1 — 2026-11-12¶

    Fase: 0 (Preparación) → inicio de la Fase 1 (Núcleo funcional).

    Objetivos de la sesión¶

    • Reconocer el entorno del PC sin modificarlo.
    • Reutilizar la infraestructura existente (Obsidian, n8n en Docker).
    • Instalar las herramientas imprescindibles con autorización.
    • Verificar VoiceStudio y su documentación oficial.
    • Crear la estructura del repositorio y el sistema de documentación.
    • Empezar el núcleo del backend.

    Tareas realizadas¶

    1. Reconocimiento del entorno con comandos de solo lectura (Get-CimInstance, Get-Command, docker inspect, Get-NetTCPConnection). Resultado en 01-analisis-entorno.md.
    2. Detección de Obsidian (v1.15.0) y de la bóveda existente Documents\Obsidian Vault, leyendo únicamente %APPDATA%\obsidian\obsidian.json. No se ha abierto ni modificado la bóveda.
    3. Inspección del contenedor n8n-local sin mostrar los valores de las variables de entorno. Se encontraba detenido; se arrancó con docker start n8n-local con autorización del usuario. Verificación: GET /healthz → 200 {"status":"ok"}.
    4. Hallazgos de seguridad en la instalación de n8n (túnel público trycloudflare.com y puerto publicado en 0.0.0.0). Documentados, no modificados (requiere decisión del usuario).
    5. Instalación autorizada de herramientas con winget (ver tabla).
    6. Verificación de VoiceStudio: lectura del README, docs/speech-platform.md, docs/api-auth.md, docs/mcp.md, docs/generation-parameters.md y docs/licensing/model-inventory.md del repositorio oficial.
    7. Revisión manual del instalador install.ps1 de VoiceStudio (148 líneas, SHA-256 del script D0B29441…F754F) antes de ejecutarlo; se lanzó en modo silencioso con autorización.
    8. Consulta de documentación oficial: modelos de OpenAI (developers.openai.com) y autenticación de la API pública de n8n (docs.n8n.io).
    9. Creación de la estructura del repositorio, del sistema de documentación y del esqueleto del backend.

    Herramientas instaladas (con autorización)¶

    astral-sh.uv 0.13.7 Instalado

    Problemas encontrados¶

    • INC-001: rustup no ofrece instalador de ámbito usuario en winget.
    • INC-002: python apuntaba al alias de la Microsoft Store (0 bytes), no a un intérprete real.
    • INC-003: la ruta REST de síntesis de VoiceStudio no aparece en la documentación pública.

    Decisiones tomadas¶

    • Arquitectura híbrida nativa en Windows (ver arquitectura/decisiones-tecnologicas.md).
    • Bóveda de memoria en %USERPROFILE%\Documents\ARVI-Memory (elegida por el usuario).
    • Modelo LLM por defecto gpt-6.1-terra, configurable.

    Resultado¶

    Entorno preparado y documentado. Pendiente al cierre: ver PROJECT_STATE.md.

    Sesión 1 (continuación) — 2026-11-12¶

    Objetivos¶

    • Implementar y probar el núcleo (Fases 1, 2 y 5).
    • Crear el sistema documental pedido: memoria en Word, web MkDocs, capturas reales.
    • Investigar el asistente telefónico (sin contratar ni activar nada).
    • Configurar notificaciones de escritorio.

    Trabajo realizado¶

    1. Backend (backend/arvi/): configuración, SQLite, LLMProvider + OpenAI + proveedor falso, memoria Obsidian con FTS5, permisos de 4 niveles, herramientas, agente y API REST/WebSocket.
    2. Pruebas: 40 pruebas automatizadas superadas (P-001) y pruebas reales P-003 a P-006.
    3. Bóveda real Documents\ARVI-Memory creada y registrada en Obsidian a petición del usuario: copia de seguridad de %APPDATA%\obsidian\obsidian.json, cierre ordenado de Obsidian y alta solo de la nueva bóveda (la bóveda personal no se modificó).
    4. Grafo de Obsidian con notas índice por categoría y colores por carpeta (petición del usuario).
    5. Documentación: 23 capítulos, fuentes reutilizables en docs/_fuentes/, mkdocs.yml con identidad visual de ARVI, Word generado y verificado, capturas F-001 y F-002.
    6. Investigación telefónica (docs/telefonia/): O2, Twilio, OpenAI Realtime SIP, ElevenLabs y módem LTE local.
    7. Notificaciones: infrastructure/scripts/notify.ps1 + hooks Notification y SessionEnd.
    8. CLAUDE.md, PROJECT_STATE.md, README.md, CHANGELOG.md y CI de GitHub Actions.

    Archivos principales creados o modificados¶

    backend/arvi/**, tests/**, config/*.yaml, pyproject.toml, mkdocs.yml, docs/**, scripts/docs/*.py, infrastructure/scripts/notify.ps1, .github/workflows/ci.yml, .claude/settings.local.json (hooks).

    Tecnologías utilizadas¶

    Python 3.12, uv, FastAPI, Pydantic, SDK openai 3.49.0, SQLite FTS5, PyYAML, psutil, pytest, Ruff, Material for MkDocs, Pandoc (pypandoc-binary, 3.9), python-docx, Playwright + Chromium, Mermaid.

    INC-004 (422 en FastAPI), INC-005 (recuento del reindexado), INC-006 (falso positivo al reiniciar), INC-007 (sobrescritura de un script de otra sesión), INC-008 (página borrada al reorganizar). Además: Obsidian mostró "Error" al abrir una bóveda no registrada con obsidian://open?path=; se resolvió registrándola (punto 3).

    Sesión 1 (cambio de modelo) — 2026-11-12¶

    • Decisión del alumno: usar de momento el modelo de OpenAI más barato.
    • Consultada la página oficial de precios: el vigente más barato con function calling y Responses API es gpt-6-luna (0,10 $/0,50 $ por millón de tokens). gpt-5-nano es más barato, pero OpenAI lo marca como obsoleto, así que se descarta.
    • Cambiado el valor por defecto en backend/arvi/config.py, .env.example y .env local (ARVI_LLM_MODEL), y actualizados el capítulo 9, ADR-003, el presupuesto y el anexo de IA.
    • Verificación: 40/40 pruebas superadas; enlaces de la documentación correctos.

    Sesión 1 (primera prueba real con OpenAI) — 2026-11-12¶

    • El alumno facilitó la clave de OpenAI; se guardó solo en .env (comprobado que Git lo ignora).
    • Al guardarla se detectó que la edición anterior de .env y .env.example con PowerShell había dañado las tildes de los comentarios (doble codificación). Se corrigió (INC-010).
    • Pruebas REALES P-007 a P-011: conversación con memoria, memory_remember, system_info, confirmación de memory_forget, aprobación sin reutilización. Coste total ≈ 0,001 $.
    • El dato de prueba «color favorito» se archivó al aprobar P-011, para no dejar información inventada en la memoria activa.
    • Criterios de aceptación 2, 5, 6 y 7: superados. Fase 1 cerrada.

    Sesión 1 (Fase 3: voz) — 2026-11-12¶

    Objetivos¶

    Interfaces de voz, VoiceStudio como motor principal, OpenAI como respaldo y medición real.

    Trabajo realizado¶

    1. Consultada la documentación oficial de OpenAI sobre audio: gpt-transcribe es el modelo de transcripción recomendado; gpt-4o-mini-tts está obsoleto y deja de funcionar el 2027-01-06.
    2. Primer arranque de VoiceStudio. Descargó ~3,4 GB y cortó temporalmente otro servicio web del alumno (INC-011). Se recuperó solo; se añadió la regla de avisar antes de descargas grandes.
    3. El alumno terminó la configuración de VoiceStudio. Antes de probar se comprobó que todos los modelos estaban en disco (OmniVoice con su tokenizador, faster-whisper-base), para no provocar descargas.
    4. Descubierta la ruta REST POST /v1/audio/speech en el openapi.json real (resuelve INC-003).
    5. Implementado backend/arvi/providers/voice/ (interfaces, VoiceStudio, OpenAI, respaldo, falsos) y la API /api/voice/{status,transcribe,speak,turn}.
    6. Mediciones de latencia (num_step 16/8/4) y corrección de «ARVI» → «Arbito» con prompt (INC-012).
    7. Pruebas REALES P-012 a P-016 y batería automática P-017 (66/66).

    Decisiones¶

    • REST en lugar de MCP para la síntesis (más simple y estándar).
    • ARVI_VOICESTUDIO_STEPS=8 por defecto, configurable; el alumno decidirá con las muestras de audio.
    • VoiceStudio solo por loopback: ARVI rechaza cualquier URL remota.

    Resultado¶

    Fase 3 completada en el backend. Quedan para la Fase 4: micrófono, reproducción con interrupción, amplitud para la esfera y síntesis frase a frase.
